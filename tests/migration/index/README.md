# Durable indexing migration proof

Run `node tests/migration/run.mjs --phase index` on the approved Windows host with MinGW GCC and WSL Ubuntu available. The runner rebuilds a private observer from unchanged locked Rust sources, validates every corpus/exporter/build input, and runs native and race checks on Windows and Linux. It also runs Go formatting, vet and module integrity checks. Full source identities and command logs are retained in `output/migration/execution/index-result.json`; an interrupted run remains incomplete.

The independent corpus covers 574 identity/catalog observations, 86 complete content workflows, 50 control workflows, 12 exact manifest cases, 109 batch histories, 284 worker wire cases and 110 notification classifications. Content cases assert real nonempty writes before comparing canonical tables, identity aliases, listings, FTS and outbox. Historical content versions 6–9 participate in real Rust→Go→Rust→Go file handoff; control checkpoints/anchors and batch notification ambiguity also cross both implementations.

Real native child tests cover three concurrent workers, nine durable pages, large pipe payloads, exact ACK correlation, incomplete output, nonzero exit after success, partial startup, cancellation, stdin closure, stderr inheritance and secret-free request files. Notification tests exercise the actual invocation arguments, private stdout identity, bounded retention with continued drainage, cancellation and inconsistent exit results.

Crash recovery force-kills the fixture process at 15 boundaries: admission, indexing, content before progress, committed progress, persisted outcome, manifest intent, outcome manifest path, immutable history, current manifest, outbox ACK, published phase, notifying phase, running attempt, successful notification and completed catalog. Each restart runs the production recovery coordinator. Tests explicitly expire dead leases after the kill instead of waiting 300 seconds. Assertions prohibit duplicate canonical articles, dropped outbox events, changed frozen bytes and repeated successful notification attempts; a running attempt retains its identity.

No public success stubs or production provider requests are used. Public CLI/registry wiring remains T11. Live Rust file handoff runs on Windows; Linux runs the same frozen corpora plus its own native process and race tests. The evidence is finite and does not claim exhaustive equivalence for every malformed input.

To intentionally refresh the oracle after a reviewed harness change, run `node tests/migration/index/build-oracles.mjs`, then each `export-identity.mjs`, `export-content.mjs`, `export-control.mjs`, `export-manifest.mjs`, `export-batch.mjs`, `export-worker.mjs` and `export-notify.mjs`. All corpora must name identical build inputs. Never regenerate expected data from the Go implementation.
