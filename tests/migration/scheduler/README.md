# Scheduler migration proof

`node tests/migration/run.mjs --phase scheduler` executes V08 on Windows and the approved native Linux toolchain in WSL. It verifies the unchanged original Rust source inventory, rebuilds locked Rust observers, validates corpus provenance, and runs regular/race Go checks, formatting, vet and dependency integrity checks. Reports and complete command logs are saved under `output/migration/execution/`.

The storage observer records 58 original histories and 241 individual transitions, including all scheduler-table SQLite values and storage classes. Go replays each history and compares every step. Twelve native Windows file handoffs exercise six histories in both Rust-to-Go and Go-to-Rust directions. JSON numeric comparison preserves exact integer identity while ignoring insignificant decimal spelling.

The worker observer compiles an unmodified copy of the original scheduler implementation with a private observation wrapper. Its 294 observations cover strict tagged jobs, filename and timing validation, all 597 accepted chrono-tz zone names, cron and DST behavior, child arguments, and bounded output summaries. `internal/platform/cron/timezones.txt` retains the original zone-name inventory; actual transition rules use the Go timezone runtime already selected in T02. Do not silently widen accepted names when updating timezone dependencies.

Native tests prove manual/automatic task exclusion across independent connections, audit rollback and administrator revocation, post-claim task changes, bounded admission capacity, monotonic cursors, ownership loss, cancellation, three real process-kill recovery boundaries, and complete descendant cleanup. Shared platform tests retain Linux parent-death and Windows Job containment evidence. Windows signed exit-code tests are intentionally platform-specific.

Scheduler children inherit stdin/stderr and receive the explicit project-root argument without changing the working directory. Index, notify and push execute sequentially under one deadline. Output captures the first 2048 bytes and summaries retain at most 4096 Unicode characters. After leader exit, Go performs bounded whole-tree cleanup before reading captured output; this removes the original unbounded wait on descendant-held stdout without leaving descendants running.

Observer regeneration is explicit: run `build-storage.mjs`, `export-storage.mjs`, `build-worker.mjs`, and `export-worker.mjs` in this directory using Node from the repository root. The unified proof runner rebuilds observers but never regenerates expected outputs. All fixtures and effects are synthetic; no external provider calls occur.
